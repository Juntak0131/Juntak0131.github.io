어떤 프로젝트인가요

회사의 서버, 노트북, 모니터, 네트워크 장비 같은 컴퓨팅 자산을 등록하고, 누가 어떤 장비를 쓰고 있는지와 시스템 사용률을 한 화면에서 보는 관리자용 웹 대시보드입니다.

장비를 사용자에게 빌려주고 돌려받은 기록이 남고, 관리자와 일반 사용자는 볼 수 있는 메뉴가 다릅니다.

맡은 파트백엔드, 화면, 배포

  • Spring Boot로 자산 등록 · 수정 · 삭제 · 검색, 사용자 할당과 반납, 대여 이력 조회 API를 만들었습니다.
  • Spring Security와 JWT로 로그인을 처리하고, 관리자와 일반 사용자 권한을 나눴습니다. 사용자 관리 화면은 관리자만 들어갈 수 있습니다.
  • AOP로 등록 · 수정 · 삭제 · 할당 · 반납 작업을 누가 언제 했는지 자동으로 기록했습니다.
  • React로 대시보드, 자산 관리, 대여 이력, 사용자 관리, 로그 화면을 만들었습니다.
  • 서버와 MySQL은 Railway, 화면은 Vercel에 배포했습니다.

어려웠던 점문제와 해결

대시보드를 어떻게 구성해야 관리자가 보기 편한지 몰랐습니다

대시보드를 만들어 본 적이 없어서, 어떤 정보를 어디에 어떻게 보여 줘야 관리자가 보기 편한지 감이 잡히지 않았습니다.

그래서 실제 회사에서 쓰는 Genian NAC 대시보드를 찾아보고, 관리자가 화면을 열었을 때 가장 먼저 확인하는 게 무엇인지부터 정리했습니다. 첫 화면 위쪽에는 전체 자산, 사용 중인 자산, 현재 CPU, 수리 · 폐기 대수를 숫자 카드로 두고, 그 아래에 시간대별 사용률 차트와 자산 상태 분포 차트를 놓았습니다.

자산 목록, 대여 이력, 로그는 왼쪽 메뉴로 나눴고, 관리자와 일반 사용자에게 보이는 메뉴를 다르게 해서 각자 필요한 화면만 보이게 했습니다.

정리한 첫 화면 구성 — 숫자 카드 → 차트 순서로 배치하고, 상세 화면은 왼쪽 메뉴로 나눴습니다.

느낀 점이 프로젝트에서 배운 것

화면을 만들기 전에 이 화면을 누가, 무엇을 확인하려고 여는지부터 정해야 구성이 정리된다는 걸 알게 됐습니다. 기능을 다 만들어 놓고 배치하는 것보다, 보는 사람이 먼저 찾는 정보부터 순서를 정하는 게 더 중요했습니다.
